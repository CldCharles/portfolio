# Internationalisation

## Deux types de textes

L’interface utilise Vue I18n : `apps/web/src/i18n/locales/{fr,en,ko}.ts`.
Le français définit le schéma ; les autres fichiers utilisent `satisfies typeof fr`.
Le code de langue du coréen est `ko`, pas `kr` (code de pays).
Les textes du CV sont stockés dans SQLite, indépendamment des libellés de l’interface.
Aucun service de traduction automatique n’est appelé.

Priorité au chargement : `?lang=fr|en|ko`, puis préférence locale, puis français.
Le sélecteur met à jour la préférence et l’URL sans supprimer les autres paramètres
ni l’ancre. Le site reste utilisable si le navigateur interdit localStorage.
`lang`, titre et description HTML suivent la langue choisie. Une réponse lente
à une ancienne sélection ne remplace pas la nouvelle langue.

## Données et révisions

`cv_items` contient les informations communes (nom, URL, dates, tags, ordre), le type
et la révision source. `cv_translations` contient titre, sous-titre, description,
langue et révision source validée, avec une clé unique `(item_id, locale)`.
Un profil unique et les entrées compétence/projet/expérience/formation utilisent
ce même mécanisme, ce qui évite quatre systèmes de traduction identiques.

Pour cette version, **le français est la source éditoriale fixe** :

- Un changement effectif du texte français incrémente sa révision.
- Les traductions existantes sont conservées ; une révision plus ancienne donne
  l’état `needs_review`. Une langue absente donne `missing`.
- La page publique utilise une traduction `current`, sinon le texte français actuel.
  Un message de repli apparaît et le bloc reçoit `lang="fr"`.
- Modifier seulement une date ou une URL ne rend pas les textes obsolètes.
- Une traduction doit être enregistrée avec la révision source attendue : une
  sauvegarde basée sur un ancien texte est refusée. Revalider un texte inchangé est possible.

Les opérations internes `saveProfile`, `saveEntry`, `setTranslation` et
`translationStatus` sont testées et utilisées par l’admin.
Elles ne sont **pas exposées par une route publique d’écriture**. L’admin dispose
d’un brouillon persistant et d’un écran de validation FR/EN/KO. Les traductions
du brouillon conservent une copie du texte source approuvé ; une différence avec
la source courante donne l’état « à vérifier ». La publication transfère les textes
et leur validation dans le système de révisions des tables publiques. Voir `docs/admin.md`.
Les textes initiaux ont été rédigés à partir des indications du propriétaire ;
les formulations françaises, anglaises et coréennes restent ajustables.

## Import LinkedIn

L’admin accepte les fichiers CSV décrits dans `docs/linkedin.md`. La langue des
textes est choisie explicitement, indépendamment des en-têtes ou de l’interface.
Un import français remplace les textes français des rubriques sélectionnées.
Un import anglais/coréen conserve sa langue comme traduction non validée ; une
version française est obligatoire, préremplie pour les rubriques existantes.
Les autres traductions sont conservées. Leur copie de source permet de détecter
si le français a changé et d’afficher « à vérifier ». Aucune traduction automatique
n’est effectuée. La validation et la publication suivent le circuit normal de l’admin.
